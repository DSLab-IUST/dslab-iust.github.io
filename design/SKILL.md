# راهنمای طراحی سایت آزمایشگاه سیستم‌های توزیعی

## چرا این جهت طراحی

سایت‌های آزمایشگاهی معمولاً یکی از دو مسیر کلیشه‌ای رو می‌رن: یا قالب دانشگاهی خشک و بی‌روح (فقط متن، بدون هویت)، یا برعکس، ظاهر یه استارتاپ SaaS با کارت‌های گرد و سایه‌ی نرم که هیچ ربطی به ماهیت پژوهش نداره. این راهنما یه مسیر سوم پیشنهاد می‌ده: **زبان بصری خودِ سیستم‌های توزیعی** — نود، لبه (edge)، اجماع (consensus)، پارتیشن، heartbeat — به‌عنوان مصالح طراحی، نه فقط موضوع محتوا.

سه اصل کلی:
1. **شبکه به‌جای تزئین** — الگوی نود/لبه فقط جایی ظاهر می‌شه که واقعاً معنا داره (هیرو، ارتباط بین حوزه‌های پژوهشی)، نه به‌عنوان پس‌زمینه‌ی تکراری روی هر بخش.
2. **رنگ کارکردی است** — هر رنگ لهجه، یه وضعیت واقعی رو نشون می‌ده (فعال/دستیافته/خطا)، نه صرفاً تزئین.
3. **مونو فقط برای داده‌ی واقعی** — فونت مونو محفوظه برای شناسه‌ی نود، تاریخ، نسخه؛ نه برای لیبل‌های تزئینی.

از این‌ها اجتناب کن (کلیشه‌های رایج طراحی تولیدشده با AI): پس‌زمینه‌ی کِرم‌گرم + رنگ سرآمیزی نارنجی‌مانند (ترکیبی که همین حالا هم رایجه)، پس‌زمینه‌ی مشکی مطلق + یه رنگ نئونی تنها، لیبل‌های ALL-CAPS بالای هر عنوان، متادیتای به‌هم‌چسبیده با نقطه‌ی وسط («A · B · C»)، و کارت‌های یکسان با همون یه شعاع گردی و سایه‌ی خاکستری روی همه‌چیز.

## پالت رنگ

| نام | Hex | نقش |
|---|---|---|
| `fabric` | `#10141F` | زمینه‌ی تیره (هدر، فوتر، هیرو) — بافت شبکه |
| `paper` | `#F5F6F8` | زمینه‌ی روشن محتوای اصلی — خنک، نه کِرم |
| `wire` | `#5B6478` | متن ثانویه، خط‌های جداکننده، لبه‌های نمودار |
| `quorum` | `#D6A93B` | حالت «فعال / اجماع دست‌یافته» — طلایی گرم |
| `link` | `#2FA6A6` | حالت «اتصال / ارجاع» — فیروزه‌ای |
| `fault` | `#C0533E` | حالت «خطا / پارتیشن» — فقط برای وضعیت واقعی خطا |
| `quorum-ink` | `#8A661F` | نسخه‌ی تیره‌تر `quorum` برای متن/آیکون روی زمینه‌ی روشن (کنتراست کافی) |
| `link-ink` | `#1C7A75` | نسخه‌ی تیره‌تر `link` برای متن روی زمینه‌ی روشن |

نکته‌ی کنتراست: `quorum` و `link` خودشون برای متن بدنه روی `paper` کنتراست کافی ندارن — فقط برای بک‌گراند تگ، آیکون، بردر و خط استفاده‌شون کن؛ برای متن از نسخه‌ی `-ink` استفاده کن.

## تایپوگرافی

یک خانواده‌ی فونت برای همه‌جا، فقط با وزن‌های مختلف تمایز ایجاد می‌کنیم (نه دو فونت جدا برای هدینگ/بدنه):

- **Vazirmatn** (variable) — برای هدینگ، بدنه، ناوبری. پشتیبانی کامل فارسی+لاتین، رایگان، طیف وزنی گسترده.
- **JetBrains Mono** — فقط برای عناصر فنی واقعی: شناسه‌ی نود، تاریخ در فهرست انتشارات، شماره‌ی نسخه، برچسب وضعیت.

قاعده‌ی عدد: در متن روایی فارسی از ارقام فارسی (۰۱۲۳)، در هر چیزی که «داده» حساب می‌شه (تاریخ‌های مونو، شناسه، شماره‌ی بند کد) از ارقام لاتین با `dir="ltr"` استفاده کن تا در RTL به‌هم نریزه.

مقیاس تایپ (طول خط بدنه حداکثر ~۶۵ کاراکتر):

| نقش | اندازه/لاین‌هایت | وزن |
|---|---|---|
| Display (هیرو) | 44/52 موبایل → 64/72 دسکتاپ | 600 |
| H1 | 32/40 | 600 |
| H2 | 24/32 | 600 |
| H3 | 20/28 | 500 |
| بدنه | 17/28 | 400 |
| متادیتا/کپشن | 14/20 | 400، رنگ `wire` |
| مونو/فنی | 13/20 | 500، رنگ `wire` یا `fabric` |

## لی‌اوت

### هیرو
دو ستونه، نامتقارن (نه وسط‌چین با گرادیان که پیش‌فرض همه‌جاست). چون RTL هست، بلوک محتوا (عنوان مأموریت آزمایشگاه + یک جمله توضیح + دکمه) سمت راست می‌شینه، و سمت چپ یه نمودار SVG از نود/لبه — نه دکوری، بلکه واقعاً نمایانگر یه تاپولوژی نیمه‌متصل (۷ تا ۹ نود، چند لبه‌ی نازک به رنگ `wire`).

```
┌─────────────────────────────────────────┐
│ fabric bg                                │
│   [نمودار نود/لبه]      [عنوان مأموریت]  │
│   (svg, می‌چیند)          [یک‌خط توضیح]   │
│                          [دکمه: پروژه‌ها] │
└─────────────────────────────────────────┘
```

حرکت: فقط یک لحظه‌ی هماهنگ‌شده در لود صفحه — لبه‌ها طی ~۹۰۰ میلی‌ثانیه یکی‌یکی رسم می‌شن، و هر نود وقتی «وصل» شد یک‌بار با رنگ `quorum` پالس می‌زنه (استعاره‌ی رسیدن به اجماع). بدون افکت هاور روی هر کارت، بدون fade-up پشت‌سرهم روی هر سکشن. با `prefers-reduced-motion` این انیمیشن غیرفعال و نمودار در حالت نهایی نمایش داده می‌شه.

### نوار آمار
به‌جای رشته‌ی به‌هم‌چسبیده با نقطه («۱۲ عضو · ۸ پروژه · ۲۴ مقاله»)، ۳ تا ۴ عدد در ردیف، هرکدوم با لیبل زیرش — بدون جداکننده‌ی تزئینی.

### حوزه‌های پژوهشی
نه گرید کارت یکسان — یک فهرست عمودی با یه خط `wire` نازک سمت راست که ردیف‌ها رو به‌هم وصل می‌کنه (همون استعاره‌ی شبکه، ولی این‌بار واقعاً کاربردی: نشون می‌ده حوزه‌ها به‌هم مرتبط‌ان). هر ردیف: یه کد کوتاه مونو + عنوان + یک‌خط توضیح.

### پروژه‌ها
۲ تا ۳ در هر ردیف. تگ وضعیت با رنگ کارکردی: «در حال انجام» = `quorum-ink`، «تکمیل‌شده/آرشیو» = `wire`. تصویر/نمودار پروژه بدون گردی گوشه (سطوح ساختاری تیز می‌مونن).

### اعضا
گرید ۲ تا ۴ ستونه، عکس + نام + نقش + یک تگ حوزه‌ی پژوهشی. بردر مویی (hairline) به‌جای سایه.

### انتشارات
فهرست، نه کارت — دقیقاً مثل قرارداد آکادمیک واقعی (شبیه al-folio): عنوان پررنگ، نویسنده‌ها، ونیو+سال با رنگ `wire`، لینک PDF/DOI/کد به‌صورت متن ساده. هر ردیف با یه خط پایین جداکننده (`border-b`).

### اخبار
فهرست فشرده معکوس‌زمانی، تاریخ به مونو (ارقام لاتین، `dir="ltr"`) + تیتر.

### فوتر
زمینه `fabric` (تقارن بصری با هیرو)، آدرس دانشکده، ایمیل، گیت‌هاب/گوگل‌اسکالر.

## گوشه‌ها و سایه

قانون ثابت واحد نداریم؛ تفاوت معنادار می‌سازیم:
- عناصر تعاملی (دکمه، اینپوت، تگ وضعیت): `rounded-sm` (شعاع ۲px)
- بلوک‌های ساختاری (کارت، تصویر، کانتینر): بدون گردی، لبه‌ی تیز
- به‌جای سایه‌ی نرم خاکستری روی همه‌چیز: بردر مویی ۱px با `wire/20` تا `wire/30`

## نکات پیاده‌سازی (Tailwind + Blazor RTL)

- با `dir="rtl"` روی `<html>`، کلاس‌های پیش‌فرض `flex` (بدون `row-reverse`) به‌طور طبیعی از راست به چپ می‌چینن — نیازی به ریورس دستی نیست.
- از یوتیلیتی‌های logical استفاده کن (`ps-*`, `pe-*`, `ms-*`, `me-*`, `start-*`, `end-*`) به‌جای `pl-*`/`pr-*` تا در حالت RTL خودکار درست بشینه.
- هر عدد/کد/شناسه‌ی فنی داخل یه `<span dir="ltr" class="font-mono">` بپیچه تا در متن RTL جهتش به‌هم نریزه.
- فوکوس کیبورد: رینگ ۲px با رنگ `link` (نه رنگ پیش‌فرض آبی مرورگر).

نمونه کلاس‌ها:
```
دکمه‌ی اصلی:  bg-fabric text-paper hover:bg-quorum hover:text-fabric
              transition-colors px-5 py-2.5 text-sm font-medium rounded-sm

تگ وضعیت:     inline-flex items-center gap-1.5 rounded-sm border
              border-wire/30 px-2 py-0.5 text-xs font-mono text-quorum-ink

ردیف انتشار:  border-b border-wire/20 py-4
```
